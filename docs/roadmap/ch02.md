# Ch02 Roadmap — Qwen3 in MoonBit

> Current native migration status and implementation notes are maintained in
> `docs/native-qwen3-moonxi-plan.md`. Native CPU and CUDA generation are working;
> the PyTorch path remains as a reference. The sections below describe the
> original PyTorch-based roadmap.

Goal: reproduce the Python book's chapter 2 (`reasoning-from-scratch/ch02`) in
MoonBit — tokenizer → model loading → Qwen3 forward pass → greedy generation
with KV cache — ending on GPU through the `zw/torch` PyTorch bridge.

## Phase 0 — Foundations (pure MoonBit, no tensors)

- [x] **Download utilities** — `utils/download.mbt`: `download_file` (skip-if-complete,
      proxy from env, redirect following, backup URL) + `qwen3_model_dir()` pointing at
      the shared cache. CLI: `moon run playground/cmd/main --target native -- download <url>`
- [~] **Tokenizer** — `qwen3/tokenizer.mbt` (byte-level BPE)
  - [ ] `Tokenizer::parse(json : String) -> Tokenizer raise TokenizerError` — parse
        tokenizer.json: vocab map, merge ranks, byte↔unicode alphabet
  - [ ] `Tokenizer::encode(self, text) -> Array[Int]` — pre-tokenize + BPE merges
  - [ ] `Tokenizer::decode(self, ids) -> String raise TokenizerError`
  - [ ] `async fn Tokenizer::load(path)` — file I/O shell around `parse`
  - Acceptance: the known-IDs test above passes; a corpus paragraph round-trips
    byte-identically
  - Fix first: `type Tokenizer` → package-private `struct Tokenizer { ... }`;
    typo `UnknowToken` → `UnknownToken`

## Phase 1 — Model loading (pure MoonBit)

- [x] **Active model loader** — `qwen3/model.mbt` uses `torch.load_safetensors`
      to produce named PyTorch tensors directly from the cached model.
- [x] **Educational native safetensors reader** — `educational/safetensors/`
  - Format: 8-byte LE header length → JSON header (name → dtype/shape/offsets) → raw bytes
  - bf16 → f32 conversion (bf16 bits `<< 16`)
  - `tensor_f32(name) -> (Array[Float], shape)` API, independent of active inference
  - Acceptance: parse the real header and verify `model.embed_tokens.weight` metadata
- [ ] **Model config** — `qwen3/config.mbt`: parse `config.json`
  (28 layers, hidden 1024, 16 q-heads / 8 kv-heads, head_dim 128,
  intermediate 3072, vocab 151936, tied embeddings, rope theta 1e6,
  rms_norm_eps 1e-6 — verified against the cached `config.json`)

## Phase 2 — CPU reference implementation (correctness first, speed never)

- [ ] **Torch tensors + ops** — `zw/torch` operations used directly by `qwen3`:
      embedding lookup, RMSNorm, matmul, RoPE, softmax, SiLU·gate (SwiGLU),
      argmax, slicing/concat. PyTorch owns kernels, shapes, strides, and
      autograd. Design principles: `docs/tensor-design.md`
- [ ] **Qwen3 forward pass** — `qwen3/model.mbt`: embed → 28 × (GQA attention +
      RoPE + RMSNorm + SwiGLU MLP) → final norm → tied-embedding logits
- [ ] **Greedy generation, no cache** — port of the book's `generate_text_basic`
- [ ] **KV cache + streaming** — port of `generate_text_basic_stream_cache`;
      cache design: immutable-first (aliasing discipline is on us — no borrow
      checker; see discussion in chat, GC prevents memory bugs not logic bugs)
- Acceptance: prompt `"Explain large language models."` produces the **same token
  IDs as the Rust port**, start to finish. CPU speed is expected to be slow
  (seconds/token) — irrelevant at this phase.

## Phase 3 — GPU via PyTorch

- [ ] Move model weights and batch tensors to CUDA with `TorchModule.to` and
      `Tensor.to`; keep all operands on the same device.
- [ ] Reuse the CPU model wiring and KV-cache logic without maintaining custom
      CUDA kernels or a second tensor implementation.
- [ ] Acceptance: same token IDs as CPU reference and Rust port; report tok/s.

## Working agreements

- No large downloads — the shared cache is the only model source.
- Every phase ends green: `moon test --target native` + `moon info && moon fmt`.
- Public APIs get explicit `raise SomeError` annotations (typed errors at
  package boundaries); internals may use bare `raise`.
- Tensors immutable by default; mutation only inside clearly-owned kernels.
- When stuck, the Rust port is the oracle — prefer matching its behavior
  byte-for-byte over improvising.
