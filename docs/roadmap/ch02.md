# Ch02 Roadmap — Qwen3 in MoonBit

Goal: reproduce the Python book's chapter 2 (`reasoning-from-scratch/ch02`) in
MoonBit — tokenizer → model loading → Qwen3 forward pass → greedy generation
with KV cache — ending on GPU via C-FFI CUDA kernels.

## Phase 1 — Model loading (pure MoonBit)

- [ ] **safetensors reader** — `qwen3/safetensors.mbt`
  - Format: 8-byte LE header length → JSON header (name → dtype/shape/offsets) → raw bytes
  - bf16 → f32 conversion (bf16 bits `<< 16`); keep bf16 raw for GPU path later
  - `tensor_f32(name) -> Tensor` API (flat F32 data plus validated shape)
  - Acceptance: read `model.embed_tokens.weight`; shape `[151936, 1024]`;
    spot-check values against the Rust loader
- [ ] **Model config** — `qwen3/config.mbt`: parse `config.json`
  (28 layers, hidden 1024, 16 q-heads / 8 kv-heads, head_dim 128,
  intermediate 3072, vocab 151936, tied embeddings, rope theta 1e6,
  rms_norm_eps 1e-6 — verified against the cached `config.json`)

## Phase 2 — CPU reference implementation (correctness first, speed never)

- [ ] **Tensor + ops** — `zw/tensor` (`Tensor`/`TensorView`, contiguous flat
      storage, naive kernels) plus `qwen3/operations.mbt`: embedding lookup,
      RMSNorm, matmul, RoPE, softmax, SiLU·gate (SwiGLU), argmax, slicing/concat.
      Design principles: `docs/tensor-design.md`
- [ ] **Qwen3 forward pass** — `qwen3/model.mbt`: embed → 28 × (GQA attention +
      RoPE + RMSNorm + SwiGLU MLP) → final norm → tied-embedding logits
- [ ] **Greedy generation, no cache** — port of the book's `generate_text_basic`
- [ ] **KV cache + streaming** — port of `generate_text_basic_stream_cache`;
      cache design: immutable-first (aliasing discipline is on us — no borrow
      checker; see discussion in chat, GC prevents memory bugs not logic bugs)
- Acceptance: prompt `"Explain large language models."` produces the **same token
  IDs as the Rust port**, start to finish. CPU speed is expected to be slow
  (seconds/token) — irrelevant at this phase.

## Phase 3 — GPU via C-FFI

- [ ] **FFI spike** — `qwen3/csrc/`: trivial C function compiled+linked through
      moon's C-stub mechanism; pass arrays via pointers both directions
- [ ] **CUDA kernel library** — nvcc → shared lib; kernels: `matmul_bf16`,
      `rmsnorm`, `rope`, `attention_gqa`, `silu_gate`, `argmax`
  - Weights copied once into C/CUDA-managed memory (keeps 1.5 GB out of the GC heap)
  - MoonBit keeps: architecture wiring, KV-cache logic, generation loop
  - Replace CPU ops one at a time, **matmul first** (~95% of FLOPs)
- [ ] Acceptance: same token IDs as CPU reference and Rust port; report tok/s

## Working agreements

- No large downloads — the shared cache is the only model source.
- Every phase ends green: `moon test --target native` + `moon info && moon fmt`.
- Public APIs get explicit `raise SomeError` annotations (typed errors at
  package boundaries); internals may use bare `raise`.
- Tensors immutable by default; mutation only inside clearly-owned kernels.
- When stuck, the Rust port is the oracle — prefer matching its behavior
  byte-for-byte over improvising.
